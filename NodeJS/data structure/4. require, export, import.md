Here’s a **summary of the usage** of `require`, `import-from`, `export`, and `export default` in JavaScript:

---

### **1. `require` (CommonJS)**
- **Purpose**: Import modules in the CommonJS module system (default in Node.js).
- **Usage**:
  ```javascript
  const module = require("module-name"); // Import a package
  const math = require("./math"); // Import a local module
  ```
- **Key Points**:
  - Synchronous.
  - Used in Node.js by default.
  - Can dynamically import modules (e.g., inside a function).

---

### **2. `import-from` (ES6 Modules)**
- **Purpose**: Import modules in the ES6 module system (modern JavaScript).
- **Usage**:
  - Import named exports:
    ```javascript
    import { add, subtract } from "./math.js";
    ```
  - Import default export:
    ```javascript
    import multiply from "./math.js";
    ```
  - Import everything:
    ```javascript
    import * as math from "./math.js";
    ```
- **Key Points**:
  - Asynchronous.
  - Requires `"type": "module"` in `package.json` for Node.js.
  - File extensions (e.g., `.js`) are mandatory.

---

### **3. `export` (Named Export)**
- **Purpose**: Export multiple values, functions, or objects from a module.
- **Usage**:
  ```javascript
  export const add = (a, b) => a + b;
  export const subtract = (a, b) => a - b;
  ```
- **Key Points**:
  - A module can have multiple named exports.
  - Must use curly braces `{}` when importing.

---

### **4. `export default` (Default Export)**
- **Purpose**: Export a single primary value, function, or object from a module.
- **Usage**:
  ```javascript
  export default function multiply(a, b) {
    return a * b;
  }
  ```
- **Key Points**:
  - A module can have only one default export.
  - No curly braces `{}` are needed when importing.
  - You can name the import anything.

---

### **Comparison Table**

| **Feature**               | **`require`**                     | **`import-from`**               | **`export`**                  | **`export default`**          |
|---------------------------|------------------------------------|----------------------------------|-------------------------------|-------------------------------|
| **Module System**         | CommonJS                          | ES6 Modules                     | ES6 Modules                   | ES6 Modules                   |
| **Import Syntax**         | `const x = require("x");`         | `import x from "x";`            | `import { x } from "x";`      | `import x from "x";`          |
| **Export Syntax**         | `module.exports = x;`            | N/A                              | `export const x = value;`     | `export default value;`       |
| **Multiple Exports**      | Not directly supported            | Supported                        | Supported                     | Not supported                 |
| **Dynamic Import**        | Supported                         | Supported with `import()`        | N/A                           | N/A                           |
| **Default Export**        | Not directly supported            | Supported                        | Not applicable                | Supported                     |
| **Node.js Support**       | Default                           | Requires `"type": "module"`      | Requires `"type": "module"`   | Requires `"type": "module"`   |

---

### **When to Use What?**
- Use **`require`**:
  - In Node.js projects using CommonJS (default for most Node.js projects).
  - When you need dynamic imports in CommonJS.

- Use **`import-from`**:
  - In modern JavaScript (ES6+).
  - When working in a browser or Node.js with `"type": "module"`.

- Use **`export`**:
  - When you need to export multiple values from a module.

- Use **`export default`**:
  - When your module has a single primary export (e.g., a function or class).
  - With export default, you can import the value with any name, making it more flexible.
  - If a module is designed to export one main thing, export default makes it clear that this is the primary export.
