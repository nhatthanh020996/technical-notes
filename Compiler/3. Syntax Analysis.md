# Article 3: Syntax Analysis - Understanding Program Structure

After our lexer has successfully broken down the source code into a stream of tokens, the next phase of the compiler, the **syntax analyzer** (or **parser**), takes over. The parser's job is to verify that this stream of tokens conforms to the language's grammatical rules and to build a data structure that represents the program's hierarchical structure.

## Grammar Fundamentals

While the lexer deals with the "words" of our language, the parser deals with the "sentences" and "phrases." We define these sentence structures using a **Context-Free Grammar (CFG)**.

### A Grammar for Our Calculator

For the calculator language we started in Article 2, we need a grammar that correctly handles operator precedence (`*` and `/` are evaluated before `+` and `-`) and associativity.

Here is a standard grammar for arithmetic expressions in **EBNF (Extended Backus-Naur Form)**:

```
expr    : term ((PLUS | MINUS) term)*
term    : factor ((MULTIPLY | DIVIDE | POWER) factor)*
factor  : (PLUS | MINUS) factor | atom
atom    : INTEGER | FLOAT | LPAREN expr RPAREN
```

Let's break this down:
*   **`expr`**: An expression is a sequence of `term`s separated by `+` or `-`.
*   **`term`**: A term is a sequence of `factor`s separated by `*`, `/`, or `^`.
*   **`factor`**: A factor can be a number (`atom`), a parenthesized expression, or a unary `+` or `-` applied to another factor.
*   **`atom`**: The most basic element, a number or a full expression in parentheses.

This structure elegantly enforces operator precedence. Because `expr` calls `term`, and `term` calls `factor`, the operators handled by `factor` (unary +/-) have the highest precedence, followed by `term`'s operators (`*`, `/`, `^`), and finally `expr`'s operators (`+`, `-`).

### Abstract Syntax Trees (AST)

The parser's output is typically an **Abstract Syntax Tree (AST)**. Unlike a parse tree, which contains all the grammatical details, an AST captures the essential structural information of the code.

For the expression `3 + 4 * 5`, the AST would look like this:

```
      + (BinaryOpNode)
     / \
    3   * (BinaryOpNode)
       / \
      4   5
```
This tree structure makes it clear that the multiplication `4 * 5` must be evaluated before its result is added to `3`.

## Parsing Technique: Recursive Descent

**Recursive Descent** is an intuitive top-down parsing strategy where each rule in our grammar is implemented as a separate function. For example, we'll have functions named `expr()`, `term()`, and `factor()`. The way these functions call each other directly mirrors the grammar's hierarchy, automatically handling operator precedence.

## Practical Implementation: Building the Parser

We will now build a parser that consumes the tokens from our `CalcLexer` and produces an AST.

### Step 1: Define the AST Nodes

First, we need classes to represent the nodes in our tree.

```python
# AST Node classes
class ASTNode:
    pass

class NumberNode(ASTNode):
    def __init__(self, token):
        self.token = token
        self.value = token[1]

    def __repr__(self):
        return f"NumberNode({self.value})"

class BinaryOpNode(ASTNode):
    def __init__(self, left_node, op_token, right_node):
        self.left_node = left_node
        self.op_token = op_token
        self.right_node = right_node

    def __repr__(self):
        return f"({self.left_node} {self.op_token[1]} {self.right_node})"

class UnaryOpNode(ASTNode):
    def __init__(self, op_token, node):
        self.op_token = op_token
        self.node = node

    def __repr__(self):
        return f"({self.op_token[1]}{self.node})"
```

### Step 2: Create the Parser Class

The parser will take the list of tokens, keep track of its current position, and provide methods to parse the grammar rules.

```python
# Inherit the CalcLexer from Article 2
# (Assuming the CalcLexer class code is present here)

class Parser:
    def __init__(self, tokens):
        self.tokens = tokens
        self.pos = 0
        self.current_token = self.tokens[self.pos]

    def advance(self):
        self.pos += 1
        if self.pos < len(self.tokens):
            self.current_token = self.tokens[self.pos]
        # No else needed, current_token will remain EOF

    def parse(self):
        if self.current_token[0] == CalcLexer.EOF:
            return None # Handle empty input
        ast = self.expr()
        if self.current_token[0] != CalcLexer.EOF:
            raise Exception("Syntax Error: Unexpected token at end of expression")
        return ast

    def factor(self):
        """Handles numbers, parentheses, and unary operators"""
        token = self.current_token
        if token[0] in (CalcLexer.PLUS, CalcLexer.MINUS):
            self.advance()
            node = UnaryOpNode(token, self.factor())
            return node
        elif token[0] in (CalcLexer.INTEGER, CalcLexer.FLOAT):
            self.advance()
            return NumberNode(token)
        elif token[0] == CalcLexer.LPAREN:
            self.advance()
            node = self.expr()
            if self.current_token[0] != CalcLexer.RPAREN:
                raise Exception("Syntax Error: Expected ')'")
            self.advance()
            return node
        else:
            raise Exception(f"Syntax Error: Unexpected token {token}")

    def term(self):
        """Handles *, /, and ^ operators"""
        node = self.factor()
        while self.current_token[0] in (CalcLexer.MULTIPLY, CalcLexer.DIVIDE, CalcLexer.POWER):
            op_token = self.current_token
            self.advance()
            right_node = self.factor()
            node = BinaryOpNode(node, op_token, right_node)
        return node

    def expr(self):
        """Handles + and - operators"""
        node = self.term()
        while self.current_token[0] in (CalcLexer.PLUS, CalcLexer.MINUS):
            op_token = self.current_token
            self.advance()
            right_node = self.term()
            node = BinaryOpNode(node, op_token, right_node)
        return node
```

## Putting It All Together: An Interpreting Calculator

To make our calculator functional, we can add an `evaluate` method to our AST nodes. This turns our compiler front-end into a complete interpreter.

```python
# Add evaluate methods to the AST nodes

class NumberNode(ASTNode):
    # ... (previous code) ...
    def evaluate(self):
        return self.value

class BinaryOpNode(ASTNode):
    # ... (previous code) ...
    def evaluate(self):
        left_val = self.left_node.evaluate()
        right_val = self.right_node.evaluate()

        op = self.op_token[0]
        if op == CalcLexer.PLUS:
            return left_val + right_val
        elif op == CalcLexer.MINUS:
            return left_val - right_val
        elif op == CalcLexer.MULTIPLY:
            return left_val * right_val
        elif op == CalcLexer.DIVIDE:
            if right_val == 0:
                raise Exception("Runtime Error: Division by zero")
            return left_val / right_val
        elif op == CalcLexer.POWER:
            return left_val ** right_val

class UnaryOpNode(ASTNode):
    # ... (previous code) ...
    def evaluate(self):
        val = self.node.evaluate()
        if self.op_token[0] == CalcLexer.MINUS:
            return -val
        return val

# Main execution loop
if __name__ == "__main__":
    # Assume CalcLexer class from Article 2 is defined here

            text = input("calc> ")
            if not text:

            # 1. Lexical Analysis
            lexer = CalcLexer(text)
            tokens = lexer.tokenize()
            print(f"Tokens: {tokens}")

            # 2. Syntax Analysis (Parsing)
            parser = Parser(tokens)
            ast = parser.parse()
            print(f"AST: {ast}")

            # 3. Evaluation (Interpretation)
            result = ast.evaluate()
            print(f"Result: {result}")

        except Exception as e:
            print(e)
```
