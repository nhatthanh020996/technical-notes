# Elasticsearch Analyzers: What, How, When

## 1. Standard Analyzer

**What**: The default analyzer in Elasticsearch that provides good results for most European languages.

**How**: Combines the standard tokenizer with lowercase filter and optional stop words.
```json
"analyzer": {
  "standard": {
    "type": "standard"
  }
}
```
Example:
```
Input: "Highlands Coffee, District 1!"
Output: ["highlands", "coffee", "district", "1"]
```

**When**: Use as a baseline analyzer for general text analysis in European languages; good starting point for most search applications.

## 2. Simple Analyzer

**What**: A basic analyzer that splits text on non-letter characters and lowercases tokens.

**How**: Uses the lowercase tokenizer which splits on non-letters and converts to lowercase.
```json
"analyzer": {
  "simple": {
    "type": "simple"
  }
}
```
Example:
```
Input: "Highlands Coffee Shop - District 1"
Output: ["highlands", "coffee", "shop", "district"]
```

**When**: Use when you need very basic tokenization without preserving numbers or special handling.

## 3. Whitespace Analyzer

**What**: Splits text on whitespace characters only.

**How**: Uses the whitespace tokenizer without additional filtering.
```json
"analyzer": {
  "whitespace": {
    "type": "whitespace"
  }
}
```
Example:
```
Input: "Highlands Coffee, District-1"
Output: ["Highlands", "Coffee,", "District-1"]
```

**When**: When you want to preserve case, punctuation, and need only basic whitespace-based splitting.

## 4. Keyword Analyzer

**What**: Treats the entire input as a single token.

**How**: Uses the keyword tokenizer that outputs the input text as a single token.
```json
"analyzer": {
  "keyword": {
    "type": "keyword"
  }
}
```
Example:
```
Input: "Highlands Coffee"
Output: ["Highlands Coffee"]
```

**When**: For exact matching of entire field values, such as categories, IDs, or codes where tokenization is not desired.

## 5. Pattern Analyzer

**What**: Uses a regular expression to split text into terms.

**How**: Combines a pattern tokenizer with lowercase and optional stop filters.
```json
"analyzer": {
  "comma_analyzer": {
    "type": "pattern",
    "pattern": ","
  }
}
```
Example:
```
Input: "coffee,tea,juice"
Output: ["coffee", "tea", "juice"]
```

**When**: When you need to split text based on specific patterns or delimiters.

## 6. Language Analyzers

**What**: Specialized analyzers for specific languages with appropriate stemming and stop words.

**How**: Combines tokenization with language-specific filters like stemmers and stop words.
```json
"analyzer": {
  "english": {
    "type": "english"
  }
}
```
Example:
```
Input: "The running cafes are closing"
Output: ["run", "cafe", "close"]
```

**When**: When working with content in a specific language that benefits from stemming and language-specific processing.

## 7. Snowball Analyzer

**What**: Uses the Snowball stemming algorithm for various European languages.

**How**: Combines standard tokenizer, lowercase, and Snowball stemmer.
```json
"analyzer": {
  "my_snowball": {
    "type": "snowball",
    "language": "English"
  }
}
```
Example:
```
Input: "running quickly to the cafes"
Output: ["run", "quickli", "to", "the", "cafe"]
```

**When**: When you need stemming for European languages and want more control than language analyzers provide.

## 8. Custom Analyzer

**What**: A configurable analyzer that combines tokenizers and filters you choose.

**How**: Explicitly specifies the tokenizer, character filters, and token filters to use.
```json
"analyzer": {
  "search_analyzer": {
    "type": "custom",
    "tokenizer": "standard",
    "filter": [
      "lowercase",
      "asciifolding"
    ]
  }
}
```
Example:
```
Input: "Café Highlands, District 1"
Output: ["cafe", "highlands", "district", "1"]
```

**When**: When you need precise control over the analysis process or when built-in analyzers don't meet your requirements.

## 9. Autocomplete Analyzer (Custom)

**What**: Specialized for handling autocomplete functionality.

**How**: Typically combines standard tokenizer with lowercase, asciifolding, and edge n-gram filters.
```json
"analyzer": {
  "autocomplete": {
    "type": "custom",
    "tokenizer": "standard",
    "filter": [
      "lowercase", 
      "asciifolding",
      {
        "type": "edge_ngram",
        "min_gram": 2,
        "max_gram": 20
      }
    ]
  }
}
```
Example:
```
Input: "Highland"
Output: ["hi", "hig", "high", "highl", "highla", "highlan", "highland"]
```

**When**: For implementing type-ahead search functionality where users get matches as they type.

## 10. Shingle Analyzer (Custom)

**What**: Creates word n-grams (shingles) for phrase matching.

**How**: Combines standard tokenizer with lowercase and shingle filter.
```json
"analyzer": {
  "shingle_analyzer": {
    "type": "custom",
    "tokenizer": "standard",
    "filter": [
      "lowercase",
      {
        "type": "shingle",
        "min_shingle_size": 2,
        "max_shingle_size": 3
      }
    ]
  }
}
```
Example:
```
Input: "Highlands Coffee Shop"
Output: ["highlands", "coffee", "shop", "highlands coffee", "coffee shop", "highlands coffee shop"]
```

**When**: When word adjacency and phrases are important, such as for business names or complete addresses.

## 11. Search-As-You-Type Analyzer Configuration

**What**: A specialized configuration for implementing search-as-you-type functionality.

**How**: Not a single analyzer but rather a field configuration that uses multiple analyzers internally.
```json
"name": {
  "type": "search_as_you_type",
  "analyzer": "search_analyzer",
  "search_analyzer": "search_analyzer",
  "max_shingle_size": 3
}
```
Example: Internally creates several fields with different analysis chains including edge n-grams and shingles.

**When**: When implementing search-as-you-type with built-in support from Elasticsearch rather than constructing custom analyzers.

## 12. Asymmetric Indexing Configuration

**What**: Using different analyzers for indexing versus searching.

**How**: Configures a field with separate `analyzer` and `search_analyzer`.
```json
"name": {
  "type": "text",
  "analyzer": "autocomplete_analyzer", // More expansive for indexing
  "search_analyzer": "simple_analyzer"  // More restrictive for searching
}
```
Example:
- At index time: "Coffee" → ["c", "co", "cof", "coff", "coffe", "coffee"]
- At search time: "Coffee" → ["coffee"]

**When**: To balance between comprehensive indexing (capturing variations) and precise searching (avoiding over-matching).

By understanding these analyzer types and their applications, you can effectively customize your Elasticsearch text analysis pipeline to deliver optimal search experiences for your users.
