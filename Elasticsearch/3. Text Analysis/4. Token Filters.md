# Elasticsearch Token Filters: What, How, When

## 1. Lowercase Filter

**What**: Normalizes tokens to lowercase for case-insensitive searching.

**How**: Applies Unicode lowercase conversion to each character in the token.
```json
"analyzer": {
  "my_analyzer": {
    "tokenizer": "standard",
    "filter": ["lowercase"]
  }
}
```
Example:
```
Input: ["Highlands", "Coffee"]
Output: ["highlands", "coffee"]
```

**When**: Almost always recommended as a basic normalization step for most search applications to ensure case doesn't affect search results.

## 2. Asciifolding Filter

**What**: Converts alphabetic, numeric, and symbolic characters that are not in the Basic Latin Unicode block to their ASCII equivalents.

**How**: Maps accented characters and other special characters to their ASCII counterparts.
```json
"filter": {
  "asciifolding": {
    "type": "asciifolding",
    "preserve_original": false
  }
}
```
Example:
```
Input: ["café", "năm"]
Output: ["cafe", "nam"]
```

**When**: When you need to handle text with accents or diacritics, especially for multilingual content like Vietnamese place names.

## 3. Stop Filter

**What**: Removes stop words (common words that add little search value) from the token stream.

**How**: Filters out tokens that match a predefined or custom list of stop words.
```json
"filter": {
  "vietnamese_stop": {
    "type": "stop",
    "stopwords": ["xã", "phường", "quận", "thành phố", "tỉnh", "huyện"]
  }
}
```
Example:
```
Input: ["quận", "1", "thành", "phố", "hồ", "chí", "minh"]
Output: ["1", "thành", "hồ", "chí", "minh"]
```

**When**: To remove common words that add noise to search results or to filter out words like administrative unit designations in addresses.

## 4. Edge N-gram Filter

**What**: Creates n-grams of specified lengths from the beginning of each token.

**How**: Generates prefix tokens from the start of each input token.
```json
"filter": {
  "autocomplete_filter": {
    "type": "edge_ngram",
    "min_gram": 2,
    "max_gram": 20
  }
}
```
Example:
```
Input: ["coffee"]
Output: ["co", "cof", "coff", "coffe", "coffee"]
```

**When**: For implementing prefix-based autocomplete where users can find matches by typing the beginning of words.

## 5. Shingle Filter

**What**: Creates word n-grams (shingles) from a token stream.

**How**: Combines adjacent tokens to form multi-word tokens.
```json
"filter": {
  "shingle_filter": {
    "type": "shingle",
    "min_shingle_size": 2,
    "max_shingle_size": 3,
    "output_unigrams": true
  }
}
```
Example:
```
Input: ["highlands", "coffee", "shop"]
Output: ["highlands", "coffee", "shop", "highlands coffee", "coffee shop", "highlands coffee shop"]
```

**When**: For phrase matching and when word order and adjacency matter, such as in business names or addresses.

## 6. Synonym Filter

**What**: Adds or replaces tokens with synonyms.

**How**: Matches tokens against a synonym mapping and adds or replaces tokens accordingly.
```json
"filter": {
  "synonym_filter": {
    "type": "synonym",
    "synonyms": [
      "cafe, coffee shop, quán cà phê",
      "restaurant, nhà hàng"
    ]
  }
}
```
Example:
```
Input: ["cafe"]
Output: ["cafe", "coffee shop", "quán cà phê"]
```

**When**: To handle different ways users might search for the same concept, particularly useful for multilingual search.

## 7. Stemming Filters

**What**: Reduces words to their root or base form.

**How**: Uses language-specific rules or algorithms to remove or replace word endings.
```json
"filter": {
  "english_stemmer": {
    "type": "stemmer",
    "language": "english"
  }
}
```
Example:
```
Input: ["running", "shops", "cafes"]
Output: ["run", "shop", "cafe"]
```

**When**: To match different forms of the same word, especially useful for content search rather than name-based entity search.

## 8. Word Delimiter Filter

**What**: Splits words on case changes, numbers, and non-alphanumeric characters.

**How**: Breaks complex tokens into simpler subwords based on character transitions.
```json
"filter": {
  "word_delimiter": {
    "type": "word_delimiter",
    "generate_word_parts": true,
    "catenate_words": true
  }
}
```
Example:
```
Input: ["HighlandsCoffee", "Coffee-Shop"]
Output: ["Highlands", "Coffee", "HighlandsCoffee", "Coffee", "Shop", "CoffeeShop"]
```

**When**: For processing compound words, camelCase terms, or hyphenated phrases where component words should be searchable individually.

## 9. Length Filter

**What**: Removes tokens that are too short or too long.

**How**: Filters tokens based on their character length.
```json
"filter": {
  "length_filter": {
    "type": "length",
    "min": 2,
    "max": 20
  }
}
```
Example:
```
Input: ["a", "coffee", "extraordinarily"]
Output: ["coffee"] (if min=2, max=10)
```

**When**: To eliminate very short tokens (like single letters) that might create noise, or extremely long tokens that might be errors.

## 10. Unique Filter

**What**: Removes duplicate tokens from the token stream.

**How**: Keeps track of tokens already seen and removes duplicates.
```json
"filter": {
  "unique_filter": {
    "type": "unique",
    "only_on_same_position": false
  }
}
```
Example:
```
Input: ["coffee", "shop", "coffee", "place"]
Output: ["coffee", "shop", "place"]
```

**When**: When you need to ensure each term is only indexed once per field, reducing index size and avoiding term frequency distortion.

Understanding these token filters and applying them appropriately will help you create powerful text analysis pipelines that match user expectations and deliver relevant search results for your place search service.
