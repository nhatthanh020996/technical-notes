# Elasticsearch Tokenizers: What, How, Where, When

## Standard Tokenizer

**What**: The default tokenizer that splits text on word boundaries based on Unicode text segmentation algorithm.
```
Input: "Highlands Coffee, District 1!"
Output: ["Highlands", "Coffee", "District", "1"]
```

**How**: Uses Unicode Text Segmentation algorithm to identify word boundaries; removes most punctuation.

**Where**: Used in the standard analyzer and as the default for many custom analyzers:
```json
"analyzer": {
  "search_analyzer": {
    "tokenizer": "standard",
    "filter": ["lowercase", "asciifolding"]
  }
}
```

**When**: The best general-purpose choice for most languages; ideal for European languages and as a baseline tokenizer.

## Whitespace Tokenizer

**What**: Divides text at whitespace characters only.
```
Input: "Highlands Coffee, District-1"
Output: ["Highlands", "Coffee,", "District-1"]
```

**How**: Simply splits on whitespace characters (spaces, tabs, line breaks); preserves punctuation.

**Where**: Used in simple analyzers or when punctuation has meaning:
```json
"tokenizer": {
  "whitespace_tokenizer": {
    "type": "whitespace"
  }
}
```

**When**: When you need to preserve punctuation or when you'll handle punctuation with character filters or token filters later.

## Keyword Tokenizer

**What**: A "non-tokenizer" that outputs the exact input text as a single token.
```
Input: "Highlands Coffee"
Output: ["Highlands Coffee"]
```

**How**: Takes the entire input as one token without any splitting.

**Where**: Used in keyword analyzer and for fields where exact matching is required:
```json
"tokenizer": {
  "keyword_tokenizer": {
    "type": "keyword"
  }
}
```

**When**: When you need exact matching on the entire field value, such as categories, IDs, or complete phrases.

## Pattern Tokenizer

**What**: Uses a regular expression to split text.
```
Input: "highlands.coffee,district:1"
Output: ["highlands", "coffee", "district", "1"] (when pattern is "[\\.,:;]")
```

**How**: Uses Java regex pattern to determine token boundaries.

**Where**: Used when standard splitting rules don't fit your needs:
```json
"tokenizer": {
  "comma_tokenizer": {
    "type": "pattern",
    "pattern": ","
  }
}
```

**When**: When you have custom delimiters or specific formatting in your text that requires custom splitting rules.

## Path Hierarchy Tokenizer

**What**: Splits hierarchical paths into tokens.
```
Input: "/home/user/documents/file.txt"
Output: ["/home", "/home/user", "/home/user/documents", "/home/user/documents/file.txt"]
```

**How**: Breaks paths at the separator (default '/') and outputs each sub-path.

**Where**: Used for hierarchical data like file paths or categories:
```json
"tokenizer": {
  "path_tokenizer": {
    "type": "path_hierarchy",
    "delimiter": "/"
  }
}
```

**When**: When searching hierarchical data where parent-child relationships matter, such as file systems, taxonomies, or location hierarchies.

## UAX URL Email Tokenizer

**What**: Like the standard tokenizer but preserves URLs and email addresses as single tokens.
```
Input: "Contact us at info@highlands-coffee.com or visit https://highlands-coffee.com"
Output: ["Contact", "us", "at", "info@highlands-coffee.com", "or", "visit", "https://highlands-coffee.com"]
```

**How**: Uses Unicode Text Segmentation with special handling for URLs and email addresses.

**Where**: Used when text contains URLs or email addresses that should be preserved:
```json
"tokenizer": {
  "url_email_tokenizer": {
    "type": "uax_url_email"
  }
}
```

**When**: When analyzing content that contains URLs or email addresses that should be searchable as complete entities.

## Classic Tokenizer

**What**: Grammar-based tokenizer designed for English.
```
Input: "The Highlands-Coffee's location is at 42.3°N"
Output: ["The", "Highlands", "Coffee's", "location", "is", "at", "42.3", "N"]
```

**How**: Uses a grammar-based tokenization algorithm that handles special cases like apostrophes in English possessives.

**Where**: Used for English-language text:
```json
"tokenizer": {
  "classic_tokenizer": {
    "type": "classic"
  }
}
```

**When**: When analyzing primarily English content with proper handling of English grammar constructs.

## Thai Tokenizer

**What**: Specific tokenizer for Thai language which doesn't use whitespace between words.
```
Input: "การค้นหาร้านกาแฟ"
Output: ["การ", "ค้นหา", "ร้าน", "กาแฟ"]
```

**How**: Uses Thai language-specific dictionary and rules to identify word boundaries.

**Where**: Used specifically for Thai language content:
```json
"tokenizer": {
  "thai_tokenizer": {
    "type": "thai"
  }
}
```

**When**: When working with Thai language text, which requires special handling because words are not separated by spaces.

Understanding these tokenizers and their appropriate use cases helps you design effective text analysis pipelines in Elasticsearch, ensuring your search results match user expectations for different languages and content types.
